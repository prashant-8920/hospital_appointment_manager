# Hospital Appointment Manager — DAA mini project

An interactive React.js application built with Vite. Patient and doctor details are entered by the user; the app does not preload hardcoded sample records. Data is persisted in browser localStorage and restored when the page is refreshed. The optional chart service uses FastAPI and Matplotlib to generate a waiting-time line chart from the scheduled appointments.

## Run the application
Open the project folder in VS Code. Install the frontend dependencies:

```powershell
npm install
```

Start the Python chart backend in one terminal:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Start the React frontend in a second terminal:

```powershell
npm run dev
```

Open the local URL printed by Vite, normally `http://localhost:5173`. The frontend requests charts from `http://127.0.0.1:8000/waiting-time-chart`. Start the backend before scheduling appointments if the Matplotlib chart is required. If it is unavailable, the rest of the dashboard remains usable and the chart panel reports the error.

The endpoint accepts JSON; `python-multipart` is not required.

To create a production frontend build:

```powershell
npm run build
npm run preview
```

Add doctors, register patients, filter doctors by specialty, then click **Schedule appointments**.

## DAA requirements covered
- **Linked List:** `PatientLinkedList` in `src/App.jsx` stores patients as nodes with `next` pointers; append is O(1).
- **Priority Queue:** `PriorityQueue` in `src/App.jsx` is a binary min-heap; priority 1 (emergency) comes before 2 (urgent) and 3 (normal). Arrival time breaks ties.
- **FIFO Queue:** `FIFOQueue` supports enqueue, dequeue, peek, and empty checks while displaying appointment results in allocation order.
- **Doctor specialization filter:** exact, case-insensitive matching.
- **Appointment allocation:** among matching doctors, choose the doctor available earliest; doctor availability advances by the 15-minute consultation duration.
- **Waiting-time distribution:** Matplotlib line chart generated by the FastAPI backend from allocated appointments.
- **Dashboard:** status, doctor, start time and waiting-time results. Clock times are entered with a time picker and displayed in 12-hour AM/PM format.
- **Persistence:** plain doctor and patient records, appointment references, and scheduling results are saved in localStorage. Patient linked-list nodes are rebuilt when saved data is loaded.
- **Algorithm explanation and complexity:** included in the webpage sidebar.

## Pseudocode
```text
Read doctor records from user input
Read patient records, including clock-time arrivals, from user input
Append each patient to linked list
Insert each patient into binary min-heap priority queue

WHILE priority queue is not empty
    patient = remove highest-priority patient
    matchingDoctors = filter doctors by patient's specialty

    IF matchingDoctors is empty
        mark patient as "No matching doctor"
    ELSE
        sort matchingDoctors by availability, then doctor ID
        doctor = first matching doctor
        start = MAX(patient arrival, doctor availability)
        waiting = MAX(0, start - patient arrival)
        doctor availability = start + 15 minutes
        record allocated appointment with patient and doctor IDs
    END IF

    enqueue appointment result in FIFO queue
END WHILE

Display dashboard and FIFO allocation order
Send allocated patient names and waiting times to the FastAPI backend
Display the returned Matplotlib line chart
```

## Complexity
Let `n` be patients, `d` be doctors, and `k_i` be the matching doctors for patient `i`.
- Linked-list append: O(1)
- Traverse patients: O(n)
- Heap insert/remove: O(log n) each
- One doctor filter: O(d)
- Sort matching doctors: O(k_i log k_i)
- Full scheduling: O(n log n + nd + sum(k_i log k_i))
- Overall storage: O(n + d + n) for doctors, patients, and appointment records

## Assumptions and limitations
- Clinic opens at 09:00 AM; arrival input accepts clock times from 09:00 AM through 09:00 PM.
- Each consultation is assumed to take 15 minutes.
- This is a batch scheduling simulation, not a real hospital booking system.
- Data is persisted in browser localStorage. There is no database or backend data store.
- The Python backend only generates charts; it does not store appointment data.
- Emergency care decisions must never rely on this demo.
